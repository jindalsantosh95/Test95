# Reward Seat Availability (Search)

Search registers `RewardSeatOperationValidationRule` alongside the enabled reward query. The host uses Hot Chocolate's unchanged `UseDefaultPipeline()`; its normal document-validation stage rejects invalid reward operations before any resolver runs. The rule traverses root selection sets iteratively, visiting each fragment once without recursive expansion. Only operations containing the reward root field receive the 1024-selection inspection limit; unrelated queries and mutations retain their existing behaviour even when reward is enabled. Distinct reward aliases, mixed root fields and deferred root fragments are rejected. Repeated ordinary fragments and merged response names are allowed, and literal `@skip(if: true)` / `@include(if: false)` branches are ignored. This is a cacheable document contract: variable-controlled branches count as potentially active, and every operation in the document must satisfy the rule, including unselected definitions. Clients should send a standalone reward operation without root `@defer`. The general operation limiter and shared account-linking document inspector retain their existing behaviour.

`rewardSeatAvailability(request)` is an optional GraphQL field in the insecure schema. It is absent unless `EnableRewardSeatAvailability=true` is explicitly set. Keep the flag false until all settings, fare-family blob rows, APIM routing, and fixture-based ITA compatibility checks are verified.

The field accepts one month/year and route. Retail Offer applies the one-adult, VS-carrier and GB market policy when calling ITA; GraphQL receives only the availability projection. It returns exactly one month containing each eligible origin-local date. Missing flights have zero points and null cash, currency, and seats. Cabin minima keep points, cash, currency, and Saver classification from the same ITA solution. Seat counts are distinct-flight inventory with daily 9/9/9 and monthly 100/50/50 default caps.

Search validates the published directed route feed and Retail Reference airport timezone before executing bounded calendar anchors through Retail Offer's internal endpoint. Disabled airport entries may be incomplete CMS placeholders and are ignored; enabled airports still require complete route data and unique airport codes. Both reference URLs must be absolute HTTPS URLs. Route and airport requests use the existing HTTP connector and its configured HTTP cache rules; each response is validated before Offer work, including when it came from that cache. Availability-only Offer work units use the registered `IDistributedCache` with a versioned key containing route, date/window, horizon, seat caps and mapping/provider versions. The availability cache defaults to 15 minutes. Setting `RewardSeatAvailability:OfferCacheTtl` to zero or an invalid value bypasses availability-cache reads and writes immediately. An incomplete unit fails the whole GraphQL field. The Bruno example is `VAA.EAPI.GraphQL.Bruno/Queries/rewardSeatAvailability.bru`.

Before enabling, set `MaxAdvanceDays` (1 to 366, based on the approved ITA horizon) and coordinated ITA and mapping versions in the GraphQL app configuration. The separate `RewardSeatOfferCalendarEndpoint` deployment parameter selects the Offer APIM calendar operation. `OfferCalendarEndpoint` must be the full calendar URL ending in `/internal/reward-seat-calendar-availability`, through the subscription-required Offer APIM route in deployed environments. Local development may call the Function directly (`/api/reward-seat-calendar-availability`). Do not append it to the booking `/Offers/` operation. For APIM, configure the existing `Search:OfferMS:OCPKey`; Search sends this subscription key without an Entra bearer token. Deployment templates do not assign Reward Seat default settings; an absent feature flag leaves the query disabled. Regular and slot environment parameter files explicitly supply the subscription-required APIM calendar endpoint. Digital and sandbox deployments require that endpoint to be configured before enablement. Set `MaxWorkUnits`, `MaxConcurrency`, and `OverallTimeoutSeconds` to approved bounded values. Retail Offer owns its GB market policy and applies it at the ITA boundary. Configure the existing `AirportInfoQuery:RoutesApi`, `RefDataMS:GenericUrl`, and `RefDataMS:OcpSubID`. `SeatCaps` overrides must be positive. Keep tokens and subscription keys in approved secret configuration; use environment-specific deployment parameters for the APIM endpoint.

Anonymous callers can use this public query without logging in. Reward availability does not require `RewardSeatAvailability:OfferAudience`, `RewardSeatAvailability:AllowedClientIds`, an Entra app registration, or an application role. These obsolete local settings can be removed. Run the public host with `OperationsVisibilityMode=Public` and `EnableRewardSeatAvailability=true`, then restart it after changing schema settings.

Availability cache exceptions are non-fatal and fall through to a live Offer call. The registered cache provider receives the request cancellation token. Reference requests use the shared HTTP caching pipeline, so its configured expiry controls their freshness. A missing or malformed route or airport response is rejected before Offer is called. `RewardSeatAvailability:OfferCacheTtl=00:00:00` only disables availability work-unit caching.

Remote Offer endpoints require HTTPS. For local Functions development, HTTP is allowed only when the configured URI is a loopback address, for example `http://localhost:7071/api/reward-seat-calendar-availability`. Match the scheme and port printed by the running Retail Offer host; pointing HTTPS at a plain HTTP port causes a TLS frame error. Restart GraphQL after changing its local settings.
