# Address Lookup v3 Suggestions and Selected-Address Retrieval — Delivery

- Status: implementation complete; external promotion evidence pending (direct implementation; no agent-loop execution)
- Owner: Loyalty Address Lookup and Account GraphQL maintainers
- Created: 2026-09-21
- Scope: Address Lookup microservice, Account GraphQL, GraphQL REST routing, no-retry connector correction, deployment templates, focused tests, and the Address Lookup v3 goal. General shared HTTP and GraphQL host security changes are split into independent platform PRs.

## Objective

Deliver the additive, secure Address Lookup v3 suggestion and selection contract while leaving the existing v2 REST and GraphQL contracts unchanged.

PR #2071 describes the final backend scope, not the historical intermediate implementations below. It adds Find-only suggestions, reference-only selected-address retrieval, public GraphQL integration, APIM/deployment support, Bruno examples and tests. Shared TLS/cache hardening (#2308), host logging/authorization (#2309) and opt-in HTTP logging (#2306) are independent drafts, not delivered controls. Shared HTTP connectors remain unchanged; the Account v3 provider uses the existing non-generic no-wait overload. The user-approved review follow-up removes REST exclusion so existing automatic routing applies. Production security approval and measured cost savings remain outstanding.

## Acceptance Criteria

- Add v3 suggestion and selection endpoints, opaque authenticated-encrypted references bound to the approved caller class and dataset (not session-bound), safe diagnostic correlation, and no automatic Retrieve retry. Do not add durable audit persistence, recovery or retention timers.
- Add public Account GraphQL v3 resolvers that use APIM through a private service subscription key and allow the existing GraphQL REST router to discover both operations without special exclusions. Retain existing configurable caching without v3-specific bypasses or no-store headers.
- Add deployment configuration and APIM policy assets for the new boundary without changing v2 credentials or routes.
- Add focused contract, gateway, security, and regression tests with run-scoped evidence.
- Keep the production canary, provider contractual confirmation, Key Vault/RBAC provisioning, and approved operational thresholds as release gates; do not misrepresent them as completed by local code.
