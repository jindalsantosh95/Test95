# Address Lookup v3 automatic container expansion

## Scope and decisions

- User requested automatic expansion before suggestions return, at most five calls at a time, merging Address candidates from the initial response and containers.
- The user's initial first-level-only preference was superseded by their request to handle nesting if Loqate supports it. [Loqate's integration guidance](https://www.loqate.com/developers/guides/address-capture-integration-best-practice/) explicitly confirms nested containers.
- Implement only inside the Address Lookup v3 application service. No shared connector, GraphQL implementation, v2, auth, Key Vault or pipeline changes.
- Breadth-first batches contain at most five Find calls. Container IDs are visited once per request and Address IDs are deduplicated before reference encryption. Every provider item with a nonblank ID and nonblank non-Address type is expandable, following the [Loqate Find Container contract](https://docs.loqate.com/api-reference/address-capture/find), including locality, building-number and sub-building levels and future navigation types.
- A defensive limit allows twenty expansion calls plus the initial Find. Pending unvisited containers after that limit return `422 SearchTooBroad` and require a narrower query. This safety bound was communicated to the user; it is not a measured optimum.
- Existing suggestion limit applies to each Find; the merged result is not truncated to six. This is not exhaustive enumeration or strict postcode matching. Automatic expansion increases Find traffic and latency, but never calls Retrieve. Selection remains unchanged.
- Await every launched batch; propagate cancellation and failures, do not return partial success or retry. Previously issued valid Container/Postcode references remain accepted.
- PR #2355 review: record each provider Find outcome at its own call boundary; record later expansion/reference failures separately with safe processing-stage telemetry. Serialize this service's test assembly because `ConfigReader.Set` writes process-wide environment variables (including shared v2/v3 keys), despite its async-local read cache. Fix the xUnit2031 assertion warning that caused the formatting gates to fail.
